# Fix Plan (2026-02-15)

## Scope

This plan addresses the review findings in `src/` with a focus on:

1. correctness bugs in duplicate/conflict checks
2. API/documentation consistency
3. decoupling core resource modeling from ORM-specific inference details
4. safer backend-facade error handling
5. stricter export format validation

The goal is to keep business/domain logic decoupled from framework/ORM internals.

## Findings -> Actions

### 1) Falsy value handling in duplicate/conflict checks

Problem:
- `0` / `False` can be treated as empty values during duplicate/conflict checks.
- This may cause false negatives in infile duplicate detection and DB-check key building.

Actions:
- Add normalized value helpers in:
  - `src/fastapi_import_export/validation_polars.py`
  - `src/fastapi_import_export/db_validation_polars.py`
- Stop using `value or ""` patterns for key/duplicate matching.
- Ensure `None` and blank-string are treated as empty, but `0`/`False` are preserved.

Tests:
- Extend `tests/test_validation_polars.py` with `0` / `False` duplicate/conflict cases.
- Extend `tests/test_db_validation.py` with `0` / `False` composite key mapping cases.

Acceptance:
- Duplicate/conflict checks correctly include `0` / `False`.

### 2) Export streaming claim vs implementation

Problem:
- README states "Streaming export payloads for large datasets", but easy-layer export serializes full payload in memory first.

Actions:
- Align docs wording to current behavior ("chunked response payloads" instead of "large dataset streaming").
- Keep implementation behavior explicit and avoid overclaim.

Files:
- `README.md`
- `README_CN.md`
- `README_JP.md`

Acceptance:
- Public docs do not overstate large-data streaming capability.

### 3) Keep core Resource model decoupled

Problem:
- `Resource` currently contains ORM-shape inference logic inline.

Actions:
- Extract model field inference logic into a dedicated helper module:
  - `src/fastapi_import_export/resource_inference.py`
- Make `Resource` call that helper, so core model declaration stays focused on mapping contract.
- Keep behavior backward-compatible (no breaking API change).

Acceptance:
- `Resource` class no longer directly implements ORM-specific field extraction branches.
- Existing tests for model-based field inference remain green.

### 4) Facade backend loading should not mask non-import errors

Problem:
- Some facades catch broad `Exception` and map to missing dependency errors.
- Runtime bugs can be masked as dependency errors.

Actions:
- In facade `_load_backend()` functions, catch only import-related exceptions:
  - `ModuleNotFoundError`
  - `ImportError`
- Preserve `ImportExportError` wrapping for genuine optional dependency absence.

Files:
- `src/fastapi_import_export/parse.py`
- `src/fastapi_import_export/validation.py`
- `src/fastapi_import_export/storage.py`
- `src/fastapi_import_export/db_validation.py`

Acceptance:
- Missing module still maps to `missing_dependency`.
- Non-import runtime exceptions are no longer swallowed as dependency errors.

### 5) Strict format validation in `service.export_table`

Problem:
- Invalid `fmt` can produce mismatched file extension/content behavior.

Actions:
- Validate `fmt` against supported values (`csv`, `xlsx`) before filename generation.
- Raise `ImportExportError` for unsupported formats with clear message.

Files:
- `src/fastapi_import_export/service.py`
- tests in `tests/test_service.py`

Acceptance:
- Unsupported format is rejected deterministically.

- Risk: behavior drift in resource model field inference.
  - Mitigation: keep existing inference logic unchanged, only move to helper module; keep tests.
- Risk: facade import behavior across environments.
  - Mitigation: catch both `ImportError` and `ModuleNotFoundError`, preserve existing error code.
- Risk: docs mismatch between languages.
  - Mitigation: update EN/CN/JP feature bullet consistently.
